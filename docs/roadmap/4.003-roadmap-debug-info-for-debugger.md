# Roadmap 4.003: debug info for a debugger

**Objective:** Land the `--debug` pipeline so the compiler attaches **LIR / TLIR source spans** and **exports meaningful information for a debugger**.

Prerequisite: solid compile / LIR / TLIR pipeline from series 1 (especially [1.002](1.002-roadmap-replace-synthesized-print.md)).

**How to execute:** one numbered macro step per implementation issue / PR (or an explicit consecutive range).

## Macro steps

### 1. `--debug` flag — LIR / TLIR source spans

**Goal:** When `--debug` is set, attach to each LIR / TLIR instruction the **original source span** of the Lovelace instructions that produced it.

- CLI: `--debug` (interaction with existing flags TBC)
- Span data on instructions in both binary `.lir` and text `.tlir` (format TBC; must round-trip)
- Docs: [`cli.md`](../cli.md), [`lir.md`](../lir.md) / text+binary companions
- Optimizers must preserve or correctly update spans → [X.002](X.002-roadmap-optimizers.md)

**Status:** Not started.

### 2. Debugger-facing export

**Goal:** Export meaningful debugger information derived from (or alongside) `--debug` spans.

- Format TBC (e.g. DWARF, custom Wasm custom sections, source maps, or a Lovelace-specific sidecar)
- Mapping from Wasm / host execution back to Lovelace source locations, locals, and call frames as far as the chosen format allows
- Stability / versioning of the debug export so IDE adapters can rely on it
- Interaction with optimizers → [X.002](X.002-roadmap-optimizers.md) (preserve or correctly update debug info)

**Status:** Not started.

## Out of scope

- IDE debugger UI / adapters → [4.004](4.004-roadmap-ide-debugger.md)
- Language feature work → series 1–2

## Status

Not started (macro steps 1–2).
