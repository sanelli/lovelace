# Roadmap 1.002: replace synthesized integer print with Lovelace

**Objective:** Add the language features needed so `augusta.std.io.print(integer)` can be implemented in Lovelace (as a normal exported interface body), leaving only a smaller synthesized primitive:

```text
PrintUTF8Character(unsigned integer<8>, unsigned integer<8>, unsigned integer<8>, unsigned integer<8>)
```

that writes the UTF-8 representation of one character (up to four octets). The public `print(integer)` stays the stable exported interface; digit formatting and control flow move into Augusta `.love` source.

Prerequisite: [1.001](1.001-roadmap-print-integer-wasi.md) (WASI print spine with temporary `native("wasi", "native-print-integer")`).

**How to execute:** one numbered macro step per implementation issue / PR (or an explicit consecutive range). Do not skip the closing Augusta rewrite and tests. After each Ada edit step, format, build, and run the relevant test crates before moving on.

## Target shape

| Layer | Role |
| --- | --- |
| `export procedure print(value : integer);` | Stable Augusta API (interface stays) |
| Lovelace body of `print` | Format decimal digits / sign using language features below |
| `@intrinsic` synthesized `PrintUTF8Character` | Smallest remaining compiler-generated UTF-8 write (1–4 octets) |

When this roadmap is done, remove synthesized `native-print-integer`. Prefer calling an `@intrinsic` `PrintUTF8Character` (name TBC) from Augusta rather than a whole-integer formatter in the backend. Distinguish **compiler intrinsics** from **real native FFI** (see locked decisions).

## Locked decisions

### Intrinsics vs native FFI

| Form | Role |
| --- | --- |
| `@intrinsic` | Compiler-synthesized body (no Lovelace instructions). **No parameters.** Matched by the compiler via a closed table keyed by **flavor + module name + procedure name + parameter types + return type** (same unqualified name may map to different bodies per flavor without clash — see [1.003](1.003-roadmap-print-integer-web.md) / [1.004](1.004-roadmap-print-integer-native.md)). |
| `@native("shared-library-name", "function-name")` | Real native / shared-library invocation (FFI). Replaces today’s overloaded use of `native("wasi", "…")` for synthesis. |

- Retire procedure-header `native("target", "key")` as the way to request **synthesized** WASI/print bodies.
- Today’s `native("wasi", "native-print-integer")` becomes an **`@intrinsic`** declaration matched by signature (exact intrinsic table locked in the implementation issue).
- **Unknown intrinsic:** if `@intrinsic` is attached to a subroutine whose signature is **not** in the closed intrinsic table, the compiler **must** emit a diagnostic (stable `LV…` code) — do not silently ignore or treat it as an ordinary empty body.
- General attribute syntax beyond these two forms → [2.012](2.012-roadmap-advanced-syntax-attributes.md); this roadmap only lands `@intrinsic` and `@native(…)`.
- Full user FFI packaging / trust → [Z.001](Z.001-roadmap-invoke-native-code.md) / [1.004](1.004-roadmap-print-integer-native.md); 1.002 establishes the **syntax split** and migrates the existing wasi print intrinsic.

Example shape (illustrative):

```love
export @intrinsic procedure PrintUTF8Character(b0, b1, b2, b3 : unsigned integer<8>);

{ later / other flavors — real shared-library call }
export @native("libaugusta", "print_utf8_character") procedure PrintUTF8Character(b0, b1, b2, b3 : unsigned integer<8>);
```

### Assignment and expressions

| Topic | Decision |
| --- | --- |
| Assignment operator | **`:=` only**; **`=`** is equality comparison |
| RHS of assignment | Any **expression** (type must be **compatible** with the LHS per the type system / cast rules below) |
| LHS of assignment | A **left-assignment expression** (lvalue). v1: a single variable. **Reserved for later** (not required in 1.002 bodies): array index (index is an expression), pointer dereference, map/dictionary access, etc. |
| Expressions | May contain **variables**, literals, operators, calls, and parenthesized subexpressions (as each lands) |
| Expression types in this slice | At least **`integer` / `integer<32>`**, **`unsigned integer<8>`**, and **`boolean`** (not only signed 32-bit) |
| Call actual parameters | Any **expression** whose type is **compatible** with the formal (same type-system rules as `:=`), including via the 1.002 cast rules |

### Type system and semantic analysis (locked)

The Lovelace **type system** and **frontend semantic analysis** are a first-class, shared compiler foundation — not ad-hoc checks scattered only in IR. Macro step **6** introduces them; **every later language feature that cares about types or definite assignment must use them**.

| Topic | Decision |
| --- | --- |
| Phase | **Semantic analysis** (name resolution / scope environment, **definite assignment**, **and** typechecker) in the **frontend** after a typed AST is available (post-parse / parser-adjacent; before or as a gate into IR lowering). Exact package name TBC (e.g. `Lovelace.Compiler.Types` / `…Typecheck` / `…Resolve` / `…Definite_Assignment`) |
| Core representation | A hierarchical / polymorphic **`Lovelace_Type`** (Ada **tagged type hierarchy**, discriminant record, or equivalent **union of kinds**) that carries **all** information needed to reason about a type: kind (`Unit`, `Boolean`, integer signedness/width, float width, …), and room to grow (arrays, records, named types, …) without rewriting call sites |
| Queries (API) | At least: **equality / same type**, **assignability** (may the value of type *A* be used where type *B* is expected?), **implicit conversion allowed?** (e.g. widening), and later **explicit cast** legality. Callers must not re-encode cast matrices inline |
| Definite assignment | A local may be **read** only if it is **definitely assigned** on every path to that use; **parameters** count as already assigned at procedure entry. Must be designed for future **path-sensitive** control flow (see step 6 and notes on `if` / loop / [2.001](2.001-roadmap-more-language-features.md) `switch`) |
| Where it applies | **Everywhere an expression is accepted**: RHS of `:=`, call actuals vs formals, operator operands / results, `if` conditions, expression-`if` arms, … — as each site lands |
| Cast policy source of truth | The 1.002 minimal cast table (and later [2.001](2.001-roadmap-more-language-features.md) matrix) is **implemented inside** the type system, not duplicated in IR |
| Migration | Existing IR-era literal checks (e.g. boolean vs integer call args from step 4) **move onto** this API once step 6 lands; IR lowering consumes already-validated types |

### Casts in this slice (minimal)

Needed so Lovelace-authored `print` can format with `integer` / `integer<32>` arithmetic and still feed `PrintUTF8Character`:

| Conversion | Kind | Notes |
| --- | --- | --- |
| `unsigned integer<8>` → `integer` / `integer<32>` | **Automatic** (widening) | No precision loss; allowed wherever an `integer<32>` is expected |
| `integer` / `integer<32>` → `unsigned integer<8>` | **Explicit cast** | Required before passing values into `PrintUTF8Character` (and similar). Syntax and range/truncation semantics **TBC** in the implementation issue — assumed needed for digit → UTF-8 octet emit |

All other signed/unsigned `integer<N>`, `float<N>`, and casts among them → [2.001](2.001-roadmap-more-language-features.md).

### Integer literals (replace `#base#`)

Retire Ada-style `#2#` / `#8#` / `#10#` / `#16#`. New prefixes:

| Prefix | Replaces | Notes |
| --- | --- | --- |
| `0b` / `0B` | `#2#` | Binary |
| `0o` / `0O` | `#8#` | Octal |
| `0x` / `0X` | `#16#` | Hexadecimal |
| *(none)* | `#10#` | Decimal only — **no** `#10#` form |

Optional sign and optional `s`/`u` + width suffixes remain as today unless a later step revises them. Update tokenizer, literal interpreter, grammar docs ([`docs/literals.md`](../literals.md), [`docs/token-grammar.md`](../token-grammar.md)), and tests; old `#base#` forms are not tokens (ordinary tokenization failure — no dedicated diagnostic).

### Float literals

| Rule | Decision |
| --- | --- |
| Default width | A float literal with `.` and/or exponent and **no** width suffix is **`float<32>`** |
| `f32` / `F32` | Trailing **`f32`** means **`float<32>`** |
| `f64` / `F64` | Trailing **`f64`** means **`float<64>`** |
| Forms | Allow `3.14`, `7.`, `1e3`, `7f32`, `2.3f64`, …; **no** lone `f`/`F`; document in [`docs/literals.md`](../literals.md) |
| Type-position `float` | Bare type `float` stays an alias of **`float<32>`** (unchanged by this step) |

### Boolean

| Topic | Decision |
| --- | --- |
| Type | **`boolean`** (frontend kind distinct from integer) |
| Literals | **`true`** / **`false`** (keywords) |
| LIR / Wasm | Maps to **`I32`**: **`false` ↔ 0**, **`true` ↔ any non-zero**; emit **0 / 1** for `false` / `true` literals |
| Language vs LIR | No boolean ↔ integer at the language level (even though both lower to i32) |
| Logical operators | Words only: `and`, `or`, `not`, `and then`, `or else` (no C-style symbols) — later macro steps |

### Numeric and comparison operators

| Class | Operators |
| --- | --- |
| Arithmetic | `+`, `-`, `*`, `/`; integers also **`mod`**, **`rem`** (keywords) |
| Comparison (→ `boolean`) | `>`, `<`, `=`, `<>`, `<=`, `>=` |

**Note:** When landing numeric and boolean expressions (macro steps 9–11), the language must support **operator precedence** and **parentheses** (`( … )`) so mixed expressions parse and evaluate unambiguously. Precedence / associativity across arithmetic, comparison, and boolean operators is locked in the first expression-operator implementation issue and documented in the grammar / expression docs; parentheses always override precedence.

### Other language pieces in this roadmap

- **`unsigned integer<8>`** in signatures and expressions (for `PrintUTF8Character` args and UTF-8 emit) — there is **no** separate `byte` type
- **Comments** in source (`{ … }`, non-nesting — see macro step 1 / #35)
- **`if` / `then` / `else`** statement and expression
- **One loop form** (flavor TBC — e.g. `while`, `loop`/`exit`, counted `for`; pick one and document). More loops → [2.001](2.001-roadmap-more-language-features.md)

## Note: evolution and eventual removal of `PrintUTF8Character`

**Internal / `@intrinsic` `PrintUTF8Character` is temporary.** Once arrays exist, prefer upgrading to a buffer primitive such as `PrintUTF8String(octets : unsigned integer<8>[])` with a synthesized array→stream wrapper — still without language async/streams (see [2.002](2.002-roadmap-arrays-type-records.md)). That wider shim (and any remaining print intrinsics) must eventually be removed once Lovelace can express the real WASI binding surface — including **async**, **await**, **future**, **stream** ([2.006](2.006-roadmap-async-await-stream.md), [3.002](3.002-roadmap-wasi-libraries.md)).

## Macro steps

### 1. Comments

**Goal:** Allow comments in `.love` so TEMPORARY notes and API docs can live in source.

**Locked:**

- Delimiters **`{` … `}`** (not `(* *)`, not `--`, not `//`)
- **No nesting:** `{` inside an open comment → `Nested_Comment` (`LV00023`); unterminated `{` → `Unterminated_Comment` (`LV00022`); stray `}` → `Stray_Comment_Closer` (`LV00024`)
- Comments are **not tokens** — skipped like whitespace; parser grammar unchanged
- Strings win: `{` / `}` inside `"…"` are not comment delimiters
- `{` / `}` are not punctuation in this slice

### 2. `@intrinsic` vs `@native(…)` (replace `native(…)`)

**Goal:** Split compiler-synthesized bodies from real native FFI in the language surface.

**Locked:**

- Forms: `[ export ] @intrinsic procedure …;` and `[ export ] @native("lib", "fn") procedure …;`
- Bare `native(…)` is not a keyword form — use `@intrinsic` / `@native` (ordinary parse failure if written as identifier `native`)
- Closed `@intrinsic` table: only `augusta.std.io.print(integer)→Unit` → existing WASI print synthesis (`Print_Integer_Stdout`)
- Unknown `@intrinsic` → `Unknown_Intrinsic` (`LV00025`)
- `@native` = parse + LIR metadata + empty noop body (no shared-library invoke yet)

Issue: [#37](https://github.com/sanelli/lovelace/issues/37). Augusta wasi arm uses `@intrinsic`; HelloPrint is the end-to-end smoke.

**Status:** In progress ([#37](https://github.com/sanelli/lovelace/issues/37)).

### 5. Variable declarations

**Goal:** Locals (and any v1 declaration sites needed for procedures) with typed names.

**Locked:**

- Block as statement: `[ declare_part ] begin { statement } end`; nested `block_statement` = block + `;`
- When `declare` is present → ≥1 `variable_declaration` (`identifier { "," identifier } ":" type_name ";"`); empty `declare` rejected
- Lexical scopes: inward visible, outward not; **no shadowing**; locals must not reuse unit name / subroutine names / parameters → `Name_Clash` (`LV00011`)
- Sibling nested blocks may reuse the same local name
- No initializers / `:=` / reads (→ step 6); module-level variables out of scope
- LIR: flat ordered locals on each subroutine (nested scopes frontend-only); binary `local_count` after params; text optional `(local …)`
- IR: DFS flatten into `Append_Local`; backend maps to Wasm core locals (`Local_Types`) — no `local.get`/`local.set` yet
- Emoji / Unicode identifiers required coverage for local, procedure, program, and module names

### 6. Assignment (`:=`) + `using` scopes + semantic typechecker / `Lovelace_Type`

**Locked:**

- Using scopes: block-scoped inward; **no shadowing** (`Name_Clash` / `LV00011`); sibling blocks OK; unit graph collects nested usings; `using … as …` still reserved → [2.001](2.001-roadmap-more-language-features.md)

- LIR `Local_Get` / `Local_Set` (1-based; params first); IR lowers assign/get; backend emits 0-based Wasm `local.get`/`local.set`

### 16. One loop form

**Goal:** Enough looping to implement digit extraction / formatting in Augusta.

- Pick **one** flavor (`while`, `loop`/`exit`, counted `for`, …); document it
- Parse + lower + tests
- **Definite assignment (step 6):** assignment **inside** the loop body does **not** imply the variable is assigned for a use that requires the body to have run — the loop may execute **zero times**.
