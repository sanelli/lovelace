# Roadmap 2.003: allocation, deallocation, pointers, and parameter modes

**Objective:** Support explicit **allocation** / **deallocation** and **pointers** so dynamic data can outlive stack frames; add **`in` / `out` / `inout` parameters**; and allow **function subroutines to return multiple values**.

Prerequisite: [2.002](2.002-roadmap-arrays-type-records.md) recommended for useful pointees; [1.002](1.002-roadmap-replace-synthesized-print.md) for basic language control flow.

## In scope

- Pointer types and dereference / address-of (syntax TBC)
- Allocate and free (or equivalent) with clear ownership rules for v1
- Diagnostics for obvious misuse where cheap (null, double-free policy TBC)
- Backend / ABI conventions for guest linear memory
- Parameter modes: **`in`**, **`out`**, **`inout`** (defaults and copy vs reference policy TBC)
- **Multiple return values** from function subroutines (syntax / tuple-like result — TBC)
- Samples + tests

## Out of scope

- Full GC
- Strings as a polished API → [2.005](2.005-roadmap-strings.md)
- Cross-component resource handles beyond what WASI already requires
- Variance of parameter/result types under subtyping → [2.009](2.009-roadmap-overload-override-mangling.md)
