# Roadmap 2.011: functional language features

**Objective:** Add a coherent set of **functional-language** features to Lovelace (exact set **TBC**), so Augusta and user code can express higher-order and declarative style without leaving the language.

Candidates to lock in the first implementation issue (illustrative, not final):

- First-class / nested functions, closures / lambdas
- Higher-order procedures (map/filter-style APIs as language or library)
- Pattern matching / destructuring (especially with [2.010](2.010-roadmap-unions-enums.md))
- Immutability / pure-by-default options (TBC)
- Partial application or currying (TBC)
- Algebraic use of `Result` / `Option`-style types once generics exist ([2.007](2.007-roadmap-templates-generics.md), [3.005](3.005-roadmap-augusta-libraries.md))

Prerequisite: expressions and control flow from [1.002](1.002-roadmap-replace-synthesized-print.md); type records / unions as needed from [2.002](2.002-roadmap-arrays-type-records.md) / [2.010](2.010-roadmap-unions-enums.md).

## In scope

- Choose and document the v1 functional feature set
- Syntax, typing, and lowering for each chosen feature
- Samples + tests

## Out of scope

- Python-like comprehensions / advanced init sugar → [2.012](2.012-roadmap-advanced-syntax-attributes.md) (may complement this roadmap)
- Full async as “functional effects” → [2.006](2.006-roadmap-async-await-stream.md)
