# Roadmap 2.015: program parameters and return value

**Objective:** Allow a **`program`** to take **parameters** like a subroutine, and to **return a number** as if it were a **function** subroutine (exit / result status for the host).

Prerequisite: parameter modes and multi-return from [2.003](2.003-roadmap-allocation-pointers.md) where useful; strings for typical CLI argv may need [2.005](2.005-roadmap-strings.md). Host wiring coordinates with WASI `cli` / native / web runners ([3.002](3.002-roadmap-wasi-libraries.md), [1.003](1.003-roadmap-print-integer-web.md), [1.004](1.004-roadmap-print-integer-native.md)).

## In scope

- Syntax for `program` parameters (same shape as subroutine parameters, or a documented subset — TBC)
- Syntax / semantics for a **numeric return** from the program body (how `return` / final expression maps to host exit code or function result — TBC)
- Lowering to the flavor entrypoint (`wasi:cli/run`, native main, web bootstrap, …)
- Passing host argv / equivalent into typed program parameters (conversion rules TBC)
- Samples + tests (including non-zero return)

## Out of scope

- Full WASI env/argv Augusta APIs beyond what this entrypoint needs → [3.002](3.002-roadmap-wasi-libraries.md)
- General multi-value program results beyond a single number (unless cheap once [2.003](2.003-roadmap-allocation-pointers.md) multi-return exists — TBC)
