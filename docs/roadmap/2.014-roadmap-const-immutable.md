# Roadmap 2.014: const and immutable modifiers

**Objective:** Add **`const`** and **immutable**-style modifiers so programmers can express different degrees of non-mutability — mixing ideas from **C++** and **Rust**.

Desired distinctions (exact keywords and rules TBC):

- A binding that **cannot be rebound** (the variable itself is fixed), while the **contents** of an aggregate/pointee may still be mutable through field access or other operations
- A stronger mode where **contents are immutable** as well (deep / shallow policy TBC)
- How these interact with pointers, `in`/`out`/`inout` ([2.003](2.003-roadmap-allocation-pointers.md)), type records ([2.002](2.002-roadmap-arrays-type-records.md)), and generics

Prerequisite: locals/assignment from [1.002](1.002-roadmap-replace-synthesized-print.md); preferably [2.002](2.002-roadmap-arrays-type-records.md) / [2.003](2.003-roadmap-allocation-pointers.md) so field and pointee mutability can be specified meaningfully.

## In scope

- Syntax for const vs immutable (or equivalent) on variables, parameters, fields, and (TBC) types
- Type-checking / diagnostics for illegal rebinding and illegal mutation
- Interaction with borrows/pointers if present
- Samples + tests covering both “fixed binding, mutable content” and “immutable content” shapes

## Out of scope

- Full ownership / borrow checker à la Rust (unless a thin subset is chosen here — TBC)
- Augusta library APIs that *use* const — libraries land in series 3
