# Roadmap 2.007: templates / generics

**Objective:** Add **templates / generics** so Augusta and user code can write reusable type-parameterized APIs (e.g. containers, `Result`/`Option`, `complex<T>`).

**Flavor TBC:** generics might attach to **modules**, and/or to **type records / subroutines** (or both). Lock the shape in the first implementation issue.

Prerequisite: [2.002](2.002-roadmap-arrays-type-records.md) (and typically [2.003](2.003-roadmap-allocation-pointers.md)) so there are useful types to parameterize; numeric generics interact with [2.001](2.001-roadmap-more-language-features.md) (remaining `integer<N>` / `float<N>`).

## In scope

- Syntax and name resolution for type parameters (module-level vs type/subroutine-level — TBC)
- Instantiation / monomorphization or equivalent lowering policy (TBC)
- Constraints on type parameters if any for v1 (may wait on [2.008](2.008-roadmap-inheritance-traits-interfaces.md))
- Samples + tests (e.g. a minimal generic container or wrapper type)

## Out of scope

- Full trait/interface system → [2.008](2.008-roadmap-inheritance-traits-interfaces.md)
- Overload / override / mangling / variance beyond what instantiation needs → [2.009](2.009-roadmap-overload-override-mangling.md)
- Per-type specializations of a generic → [2.013](2.013-roadmap-generic-specializations.md)
- Shipping Augusta containers/crypto/etc. → [3.004](3.004-roadmap-augusta-libraries.md) (depends on this roadmap)

Not started.
