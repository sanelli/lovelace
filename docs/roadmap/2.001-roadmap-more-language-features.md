# Roadmap 2.001: more language features

**Objective:** Grow the sequential language with additional control-flow, import, numeric-type, and casting constructs beyond the minimal set in [1.002](1.002-roadmap-replace-synthesized-print.md) (which lands one initial loop flavor plus `if`/expressions, `unsigned integer<8>` in expressions, and only the two cast rules needed for Lovelace-authored `print`).

Prerequisite: [1.002](1.002-roadmap-replace-synthesized-print.md). Type records / nested imports interact with [2.002](2.002-roadmap-arrays-type-records.md). Builds on unit-level `import` from [1.001](1.001-roadmap-print-integer-wasi.md).

## In scope

- **More loop forms** not covered by the first loop in 1.002 — e.g. `for`, `until`, `forever`, and similar (exact set and syntax TBC)
- **`switch` / `case` expression**
- **`switch` / `case` statement**
- **Blocks as expressions** — a block can yield a value that may be assigned (`:=`) or discarded
- **Other constructs** drawn from familiar languages where they fit Lovelace’s design (lock per implementation issue)
- **Nested `import`** inside subroutines, type records, code blocks, and similar scopes (not only file-leading unit imports)
- **`import X as Y`** — import a module under an alias (reserved in 1.001; implement here)
- **Unqualified use after import** — ability to `import` module `X` and call its exported subroutines **without** prepending `X.` (exact syntax / “use all” form TBC; must stay unambiguous with local names)

### Definite assignment (extends [1.002](1.002-roadmap-replace-synthesized-print.md) step 6)

Any new control-flow form here **must** extend the shared **definite-assignment** analysis (not a one-off parser check):

| Construct | Note |
| --- | --- |
| **Additional loops** | Same as 1.002 step 14: body may run zero times; assignment in the body alone does not assign for “after loop” / “before first iteration” uses unless other paths assign |
| **`switch` / `case` statement or expression** | A variable is assigned after the switch only if assigned on **every** completing alternative (including `default` / missing-default policy locked with the grammar). Fall-through, if any, must be modeled explicitly |
| **Expression blocks** | Assignments inside a block that always runs assign for subsequent code in the enclosing flow; early exit / incomplete paths TBC with the construct |

Parameters remain “already assigned”; locals still may not be read until definitely assigned on all paths to the use.

### Remaining numeric types

[1.002](1.002-roadmap-replace-synthesized-print.md) already uses sized integers in the type system for signatures and lands **expression** support for `integer` / `integer<32>` and `unsigned integer<8>` (plus float **literal** forms). This roadmap completes **expression / operator / lowering** support for the rest of the intended widths:

- All other signed / unsigned **`integer<N>`** (e.g. 8/16/32/64 as applicable beyond the 1.002 slice)
- All **`float<N>`** as first-class expression types (beyond literal spelling from 1.002)

### Casting matrix

| Allowed | Rule |
| --- | --- |
| **Automatic** | Only where **no precision is lost** (e.g. widening integer→integer, or other lossless promotions locked in the implementation issue) |
| **Explicit** | Lossy or non-obvious conversions (narrowing, float↔integer, etc.) — syntax TBC; never silent when precision would be lost |
| **Forbidden** | Across **incompatible** types — including **boolean ↔ integral**, **integral ↔ enum** (even if enums are stored as integrals in LIR/Wasm), and similar category mismatches |

1.002 already locks: automatic `unsigned integer<8>` → `integer<32>`, and explicit `integer<32>` → `unsigned integer<8>`. This roadmap generalizes that policy across the full numeric set.
